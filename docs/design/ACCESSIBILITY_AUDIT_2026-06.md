# Muninn Webview — WCAG 2.1 AA Accessibility Audit (June 9, 2026)

Static code audit of the editor webview (`src/webview/editor/`), against WCAG 2.1 AA. Method: review of DOM construction (`bootstrap.ts`), interaction logic (`index.ts`), node views (`nodes/table-node-view.ts`), Mermaid rendering (`preview.ts`), and styles (`styles.css`). Not yet performed: live screen-reader passes (VoiceOver/NVDA), which should follow the P1 fixes — automated/static review typically surfaces only a minority of real-world issues.

## Baseline strengths (keep these)

The codebase is unusually conscientious for the category. Verified in code: `role="toolbar"` with `aria-label`, button groups using `role="group"` + `aria-labelledby` (`bootstrap.ts:27-44`); managed `aria-pressed` state on toggle buttons (`index.ts:702-710`); `aria-expanded` on the More toggle with deliberate focus fallback when advanced actions hide (`index.ts:170-183, 692-700`); status line as `role="status"` `aria-live="polite"` (`bootstrap.ts:61`); table cell inputs with per-cell coordinate `aria-label`s (`table-node-view.ts:479-485`); table source textarea with `aria-label` + `aria-describedby` + `aria-keyshortcuts` and polite live feedback (`table-node-view.ts:340-356`); code-block language select labeled (`table-node-view.ts:107`); `:focus-visible` outlines on every interactive element using `--vscode-focusBorder`; all colors via VS Code theme tokens (contrast tracks the user's theme, including high-contrast themes); `color-scheme: light dark`; no animations (no reduced-motion concerns); escaped l10n HTML; sanitized Mermaid SVG.

## Findings

Severity: **P1** = blocks a class of users / clear AA failure · **P2** = significant friction · **P3** = polish.

| # | Sev | WCAG | Finding | Location | Recommendation |
|---|---|---|---|---|---|
| 1 | P1 | 2.1.1, 2.4.3 (toolbar pattern) | Every toolbar button is a tab stop — no roving tabindex or arrow-key navigation. Keyboard users tab through up to 13 controls to reach the document; `role="toolbar"` sets the expectation of the ARIA toolbar pattern (one tab stop, arrows within). | `bootstrap.ts:27-51`, `index.ts:663` | Implement roving tabindex: toolbar is a single tab stop; Left/Right arrows move between buttons, Home/End jump; Tab exits to the editor. |
| 2 | P1 | 1.1.1 | Rendered Mermaid SVGs have no text alternative — no `role="img"`, no `aria-label`/`<title>`. Diagrams are invisible to screen readers in both the global preview panel and per-block previews. | `preview.ts:68` (innerHTML injection), `table-node-view.ts:114` | After sanitize, set `role="img"` and an `aria-label` derived from the diagram source (first line / diagram type), and keep the source code block reachable as the full alternative. |
| 3 | P1 | 1.3.1 | Table grid semantics incomplete: `<th>` lacks `scope="col"`; the grid `<table>` has no caption or accessible name, so multiple tables in a document are indistinguishable; header/data relationships rely solely on per-input `aria-label`s. | `table-node-view.ts:448-471` | Add `scope="col"`, plus `aria-label` (or visually-hidden caption) on each grid table, e.g. "Table 2, 3 columns × 4 rows". |
| 4 | P1 | 2.4.3 | Enter in a table cell calls `input.blur()` — focus is dropped to `<body>`; keyboard users lose their place after every commit. | `table-node-view.ts:490-495` | Commit on Enter without blurring, or move focus to the same column in the next row (spreadsheet convention). Add Escape = revert-and-stay. |
| 5 | P2 | 2.1.1 | No arrow-key navigation between table cells; moving through the grid requires Tab-walking every input. | `table-node-view.ts:476-497` | Optional grid pattern: Up/Down/Left/Right between cells when caret is at input boundary. |
| 6 | P2 | 4.1.2 | Editor surface (ProseMirror `contenteditable`) has no accessible name; SR users land on an unlabeled editable region. | `bootstrap.ts:59`, `index.ts:781` | Set `aria-label` (localized "Markdown editor — <filename>") on the ProseMirror root via EditorView `attributes`. |
| 7 | P2 | 4.1.3, 3.3.1 | Command failures and successes share one polite status channel and identical presentation; failures ("No table found…") are easy to miss and carry no error semantics. | `index.ts:678-687`, `bootstrap.ts:61` | Keep `role="status"` for successes; route failures through an assertive channel (`role="alert"`) or prefix with a localized "Error:". |
| 8 | P2 | 1.4.1 | Table source-apply feedback distinguishes success/error by color class only (`is-success`/`is-error`); text content may not always disambiguate. | `styles.css:389-395`, `table-node-view.ts:356` | Ensure feedback strings are explicit ("Applied" / "Error: …") and/or add an icon — never color alone. |
| 9 | P2 | 1.3.1 | Mermaid preview `<section>` has no accessible name, and its show/hide on selection change is not announced. | `bootstrap.ts:53-58`, `preview.ts` | `aria-label` on the section; announce "Diagram preview shown/hidden" via the status line. |
| 10 | P3 | 4.1.2 | `aria-expanded` on More button has no `aria-controls`; revealed buttons are scattered across groups rather than adjacent to the toggle. | `bootstrap.ts:50`, `index.ts:132-146` | Add `aria-controls` (wrap advanced items or list IDs); already-good focus management mitigates. |
| 11 | P3 | 1.3.1, 2.4.6 | Webview has no heading structure; header brand uses `<strong>`. Minor for an editor surface, relevant once dialogs/panels multiply. | `bootstrap.ts:20-26` | Low priority; consider `<h1 class="visually-hidden">` document title. |
| 12 | P3 | 1.4.4 | Root font fixed at `13px`; webview text does not follow VS Code's `editor.fontSize`/zoom beyond webview zoom. | `styles.css:1-4` | Derive type scale from `--vscode-font-size` (e.g. `font-size: var(--vscode-font-size, 13px)`). |
| 13 | P3 | 2.5.5 (AAA, noted) | 32px min-height controls; below the 44px AAA target (AA 2.1 has no minimum; WCAG 2.2's 2.5.8 24px is met). | `styles.css:92-98` | No action required for AA; keep ≥24px. |

## Suggested order of work

Findings 1–4 (P1) are one focused pass over `bootstrap.ts`, `table-node-view.ts`, and `preview.ts` — estimate 2–3 evenings including E2E coverage (the WDIO suite can assert roving tabindex and focus retention). Then run live VoiceOver + NVDA passes and fix what they surface (expect items around ProseMirror announcement behavior). After that, the README can honestly state: "Audited against WCAG 2.1 AA; conformance notes published" — which no competitor in the niche currently claims. Re-audit at GA and when the toolbar gains new controls.
